# NestJS v10 → v11 Migration Guide

Source: https://docs.nestjs.com/migration-guide

Full list of breaking changes: https://github.com/nestjs/nest/releases/tag/v11.0.0

## Upgrading packages

Use [npm-check-updates (ncu)](https://npmjs.com/package/npm-check-updates) for a streamlined upgrade:

```bash
npx npm-check-updates -u
npm install
```

Or upgrade manually:

```bash
npm install @nestjs/common@11 @nestjs/core@11 @nestjs/platform-express@11
# repeat for all @nestjs/* packages in use
```

## Breaking changes

### Express upgraded to v5 (default platform)

`@nestjs/platform-express` v11 uses Express v5. Review the [Express v5 migration guide](https://expressjs.com/en/guide/migrating-5.html) for the full list of changes. Key impacts on NestJS routes:

**Wildcard routes must be named:**

```typescript
// Before (Express v4 syntax — no longer valid)
@Get('users/*')
findAll() {}

// After (Express v5 syntax)
@Get('users/*splat')
findAll() {}

// To also match the root path /users:
@Get('users/{*splat}')
findAll() {}
```

**Middleware applied to all routes:**

```typescript
// Before
forRoutes('*');

// After — braces make the wildcard optional (matches root path too)
forRoutes('{*splat}');
```

**Optional parameter syntax changed:**

```typescript
// Before
@Get(':file.:ext?')

// After
@Get(':file{.:ext}')
```

**Regexp characters no longer supported in paths.**

Characters `(()[]?+!)` are reserved — escape them with `\` if needed.

### Query parameters parsing change (Express v5)

Express v5 uses a `simple` parser by default instead of `qs`. Nested objects and arrays in query strings are no longer parsed automatically.

If your app uses query strings like `?filter[where][name]=John` or `?item[]=1&item[]=2`, restore the previous behavior:

```typescript
import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule);
  app.set('query parser', 'extended'); // restores qs behavior
  await app.listen(3000);
}
bootstrap();
```

### Fastify upgraded to v5

`@nestjs/platform-fastify` v11 uses Fastify v5. Review the [Fastify v5 migration guide](https://fastify.dev/docs/v5.1.x/Guides/Migration-Guide-V5/). Path matching for routes is unchanged; only middleware path matching is affected (see below).

**Fastify CORS — explicit methods required:**

Only CORS-safelisted methods (`GET`, `POST`, `HEAD`) are allowed by default. If you use `PUT`, `PATCH`, `DELETE`, declare them explicitly:

```typescript
app.enableCors({ methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE'] });
```

**Fastify middleware paths — named wildcards required:**

```typescript
// Before
.forRoutes('(.*)');

// After
.forRoutes('*splat');
```

### Module resolution algorithm changed

Dynamic modules no longer use predictable hash-based deduplication. Instead, object reference equality is used. To share a dynamic module across multiple feature modules, extract it to a shared variable:

```typescript
// shared-cache.module.ts
export const SharedCacheModule = CacheModule.register({ ttl: 300 });

// feature-a.module.ts
@Module({ imports: [SharedCacheModule] })
export class FeatureAModule {}

// feature-b.module.ts
@Module({ imports: [SharedCacheModule] })
export class FeatureBModule {}
```

**Impact on tests:** Without explicit deduplication, `TestingModule` may have multiple instances of a dependency. Options:

```typescript
// 1. Deduplicate the module as shown above

// 2. Select the correct instance
module.select(ParentModule).get(Target)

// 3. Stub all instances
module.get(Target, { each: true })

// 4. Revert to the old algorithm
Test.createTestingModule({}, { moduleIdGeneratorAlgorithm: 'deep-hash' })
```

### Lifecycle hooks execute in reverse order on shutdown

Termination hooks (`OnModuleDestroy`, `BeforeApplicationShutdown`, `OnApplicationShutdown`) now run in **reverse dependency order** relative to initialization.

Given `A → B → C` (A depends on B, B depends on C):
- Init order: `C → B → A`
- Destroy order: `A → B → C`

### Global middleware runs first

Middleware registered in global modules now always executes **before** middleware from imported modules, regardless of the module dependency graph position.

### Reflector type inference improvements

1. `getAllAndMerge` returns a merged object (not a single-element array) when there is only one object metadata entry.
2. `getAllAndOverride` return type is now `T | undefined` instead of `T`.
3. `ReflectableDecorator` transformed type argument is properly inferred across all methods.

### Cache module — migrated to Keyv

`@nestjs/cache-manager` now uses [Keyv](https://keyv.org/) for the storage backend. The configuration API changed:

```typescript
// Before
CacheModule.registerAsync({
  useFactory: async () => {
    const store = await redisStore({ socket: { host: 'localhost', port: 6379 } });
    return { store };
  },
}),

// After
import { KeyvRedis } from '@keyv/redis';

CacheModule.registerAsync({
  useFactory: async () => ({
    stores: [new KeyvRedis('redis://localhost:6379')],
  }),
}),
```

> **Note:** Cached data is now stored as `{ "value": "...", "expires": 1678901234567 }`. Direct cache reads outside the `cache-manager` API will see this structure.

### Config module (`@nestjs/config`) — priority order changed

In `@nestjs/config@4.0.0`, `ConfigService#get` now reads in this order (highest to lowest priority):

1. Internal config (namespaces / custom config files)
2. Validated environment variables (if schema provided)
3. `process.env`

Previously `process.env` and validated env vars took precedence over internal config. Update your config setup if you relied on env vars overriding internal config.

**`ignoreEnvVars` deprecated** — use `validatePredefined: false` instead.

**New `skipProcessEnv` option** — prevents `ConfigService#get` from reading `process.env` at all.

### Terminus module — new `HealthIndicatorService` API

The `HealthIndicator` base class and `HealthCheckError` are deprecated (removed in v12). Migrate custom health indicators to use `HealthIndicatorService`:

```typescript
// Before
@Injectable()
export class DogHealthIndicator extends HealthIndicator {
  async isHealthy(key: string) {
    const isHealthy = (await this.getBadboys()).length === 0;
    const result = this.getStatus(key, isHealthy);
    if (!isHealthy) throw new HealthCheckError('Dog check failed', result);
    return result;
  }
}

// After
@Injectable()
export class DogHealthIndicator {
  constructor(private readonly healthIndicatorService: HealthIndicatorService) {}

  async isHealthy(key: string) {
    const indicator = this.healthIndicatorService.check(key);
    try {
      const isHealthy = (await this.getBadboys()).length === 0;
      return isHealthy ? indicator.up() : indicator.down({ badboys: true });
    } catch {
      return indicator.down('Unable to retrieve dogs');
    }
  }
}
```

### Node.js v16 and v18 dropped

NestJS v11 requires **Node.js v20 or higher**. Node.js v16 (EOL Sep 2023) and v18 (security EOL Apr 2025) are no longer supported.
