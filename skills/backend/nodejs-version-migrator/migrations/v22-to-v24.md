# Node.js v22 → v24 Migration Guide

> Reference: https://nodejs.org/en/blog/migrations/v22-to-v24  
> v23.0.0 release notes: https://nodejs.org/en/blog/release/v23.0.0  
> v24.0.0 release notes: https://nodejs.org/en/blog/release/v24.0.0

> **Note:** v23 was never an LTS release. This guide covers the breaking changes
> introduced across both v23 and v24 that affect an application migrating
> directly from v22 LTS to v24 LTS.

## Contents

- Codemods
- Breaking changes
- Deprecated APIs to migrate (runtime warnings, must fix before v25)
- Infrastructure and tooling updates
- Notable v24 additions

## Codemods

Run all applicable codemods **before** making manual changes:

```bash
# RSA-PSS key generation options renamed
npx codemod run @nodejs/crypto-rsa-pss-update

# dirent.path → dirent.parentPath
npx codemod run @nodejs/dirent-path-to-parent-path

# fs.F_OK / R_OK / W_OK / X_OK → fs.constants.*
npx codemod run @nodejs/fs-access-mode-constants

# fs.truncate(fd, ...) → fs.ftruncate(fd, ...)
npx codemod run @nodejs/fs-truncate-fd-deprecation

# process.assert → node:assert
npx codemod run @nodejs/process-assert-to-node-assert
```

## Breaking changes

### Platform support dropped

| Platform | Dropped in |
|---|---|
| 32-bit Windows (x86) | v23.0.0 |
| 32-bit Linux armv7 | v24.0.0 |
| 32-bit ppc | v24.0.0 |
| 32-bit s390 | v24.0.0 |
| macOS < 13.5 | v24.0.0 |
| MSVC compiler on Windows | v24.0.0 (use ClangCL instead) |

### OpenSSL 3.5 security level raised

Node.js 24 ships OpenSSL 3.5 with a default security level of `2`. This means:

- RSA, DSA, and DH keys **shorter than 2048 bits** are rejected.
- ECC keys **shorter than 224 bits** are rejected.
- Any cipher suite using **RC4** is rejected.

Audit your TLS configuration and key sizes before upgrading. To test, run your application against a Node.js 24 build and observe TLS handshake errors.

### `process.assert` removed

`process.assert()` was removed entirely. Run the codemod or replace manually:

```js
// Before
process.assert(condition, 'message');

// After
const assert = require('node:assert');
assert(condition, 'message');
```

### `dirent.path` removed (use `dirent.parentPath`)

`dirent.path` was runtime-deprecated in v23, then **removed** in v24. Run the codemod or replace manually:

```js
// Before
entries.forEach(dirent => console.log(dirent.path));

// After
entries.forEach(dirent => console.log(dirent.parentPath));
```

### `fs.truncate` with a file descriptor removed

Calling `fs.truncate(fd, len, cb)` with a numeric file descriptor was removed. Use `fs.ftruncate` instead:

```js
// Before
fs.truncate(fd, 10, callback);

// After
fs.ftruncate(fd, 10, callback);
```

### `tls.createSecurePair` removed

`tls.createSecurePair()` was removed entirely. Migrate to `tls.TLSSocket`:

```js
// Before
const pair = tls.createSecurePair(ctx, isServer);

// After
const socket = new tls.TLSSocket(rawSocket, { secureContext: ctx, isServer });
```

### `http.OutgoingMessage._headers` and `_headersList` removed

These internal properties were removed. Use the public API:

```js
// Before
const headers = res._headers;

// After
const headers = res.getHeaders();
```

### `--experimental-permission` flag renamed to `--permission`

If your start scripts or CI configs use `--experimental-permission`, update them:

```bash
# Before
node --experimental-permission --allow-fs-read=. app.js

# After
node --permission --allow-fs-read=. app.js
```

### `fs.F_OK`, `fs.R_OK`, `fs.W_OK`, `fs.X_OK` runtime deprecated then removed

Access mode constants are no longer exported directly from `fs`. Run the codemod or update manually:

```js
// Before
fs.access(path, fs.R_OK, callback);

// After
fs.access(path, fs.constants.R_OK, callback);
```

### Stream pipe to a closed/destroyed stream now throws

Piping to an already closed or destroyed writable stream now raises an error instead of silently failing:

```js
// This will now emit an 'error' event or throw instead of being silently ignored
readable.pipe(closedWritable);
```

Audit all `pipe()` call sites to ensure the destination stream is open before piping.

### `buffer.write()` beyond buffer bounds now throws

Writing beyond the buffer boundary now throws a `RangeError` instead of silently truncating. Audit any code that writes near the end of a buffer.

### `timers.setInterval` / `setTimeout` with negative or NaN delay now warns

Passing a negative or `NaN` value as the delay now emits a deprecation warning. Replace with `0` or a positive number.

### Test runner: `t.test()` / `test()` no longer return promises

The return values of `t.test()` and `test()` were changed. If your code awaited these calls to sequence test execution, remove the `await` — the runner now automatically waits for subtests:

```js
// Before (no longer needed)
await t.test('subtest', () => {});

// After
t.test('subtest', () => {});
```

### Test runner: `spec` is now the default reporter

The default test reporter changed from `tap` to `spec`. If your CI pipeline parses TAP output, add `--test-reporter=tap` explicitly.

### Crypto: RSA-PSS key generation options renamed

`hash`, `mgf1Hash` → `hashAlgorithm`, `mgf1HashAlgorithm` (run the codemod):

```js
// Before
crypto.generateKeyPair('rsa-pss', {
  modulusLength: 2048,
  hash: 'sha256',
  mgf1Hash: 'sha1',
});

// After
crypto.generateKeyPair('rsa-pss', {
  modulusLength: 2048,
  hashAlgorithm: 'sha256',
  mgf1HashAlgorithm: 'sha1',
});
```

### `assert`/`util`: WeakMap and WeakSet comparison changed

`assert.deepEqual` and `util.isDeepStrictEqual` now compare `WeakMap` and `WeakSet` contents, rather than treating all instances as equal. Tests relying on the old shallow comparison behaviour may fail.

### `require(esm)` enabled by default (v23+)

`require()` can now load synchronous ESM graphs without a flag. This may cause packages that previously resolved as CJS to resolve differently. Check for:

- `ERR_REQUIRE_ASYNC_MODULE` — the ESM module contains top-level `await`. Either use dynamic `import()` or ensure the module is sync.
- Changed namespace object shapes — `require()` now returns a module namespace object; properties previously on `module.exports` are now named exports.

### `util.is*` helpers and `util.log` removed (end-of-life)

These were runtime-deprecated in v22 and reached end-of-life in v23 (removed). See the v20→v22 guide for the full replacement table. Grep and fix any remaining usages:

```bash
grep -rn "util\.is\|util\.log\b\|util\._extend" . --include="*.js" --include="*.ts"
```

### `--trace-atomics-wait` flag removed

Remove this flag from any scripts or CI configuration.

### `NODE_MODULE_VERSION` bumped to 137

All native addons must be recompiled against v24 headers.

## Deprecated APIs to migrate (runtime warnings)

These APIs emit runtime deprecation warnings in v24 and will be removed in v25.
Fix them during this migration to avoid a second breaking-change cycle.

| API | Replacement |
|---|---|
| `url.parse()` | `new URL(string)` |
| `SlowBuffer` | `Buffer.alloc()` / `Buffer.from()` |
| `new require('node:repl').REPLServer(...)` without `new` | Use `new` keyword |
| `new Zlib*()` without `new` (e.g. `zlib.Gzip()`) | Use `new zlib.Gzip()` |
| `child_process.spawn(cmd, args, opts)` / `execFile(cmd, args, opts)` — passing `args` separately | Pass options directly |
| `crypto.fips` getter/setter | `crypto.getFips()` / `crypto.setFips()` |
| `net._setSimultaneousAccepts()` | Remove — no replacement |
| `tls.Server.prototype.setOptions()` | `tls.Server.prototype.setSecureContext()` |
| `fs.existsSync(invalidType)` with non-string | Validate input type before calling |

Grep for `url.parse`:

```bash
grep -rn "url\.parse(" . --include="*.js" --include="*.ts"
```

Grep for `SlowBuffer`:

```bash
grep -rn "SlowBuffer" . --include="*.js" --include="*.ts"
```

## Infrastructure and tooling updates

### `.nvmrc` / `.node-version`

```
24
```

### `package.json` engines

```json
"engines": { "node": ">=24.0.0", "npm": ">=11.0.0" }
```

### Dockerfile

```dockerfile
# Before
FROM node:22-bookworm-slim

# After
FROM node:24-bookworm-slim
```

### TypeScript (`tsconfig.json`)

Node.js 24 fully supports ES2024:

```json
{
  "compilerOptions": {
    "target": "ES2024",
    "lib": ["ES2024"]
  }
}
```

### CI/CD (GitHub Actions example)

```yaml
- uses: actions/setup-node@v4
  with:
    node-version: '24'
```

## Notable v24 additions (no action required, but worth adopting)

- **`AsyncLocalStorage` uses `AsyncContextFrame`** by default — improved performance for context propagation
- **`URLPattern` global** — available without import; remove manual `URLPattern` polyfills
- **Explicit resource management** (`using` / `await using`) enabled natively
- **`Float16Array`** — new typed array class available globally
- **`Error.isError()`** — reliable cross-realm error detection
- **`fetch()` HTTP proxy support** via `NODE_USE_ENV_PROXY` environment variable
- **Undici 7** bundled — improved HTTP client performance
- **npm 11** bundled
- **Type stripping** for `.ts` files (RC status) — run TypeScript natively without a build step
