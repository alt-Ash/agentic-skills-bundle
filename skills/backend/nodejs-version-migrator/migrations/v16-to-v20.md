# Node.js v16 → v20 Migration Guide

> **This is a two-hop migration**: v16 → v18 → v20. Complete all steps for hop 1
> and verify tests pass before starting hop 2.

## Contents

- Hop 1: v16 → v18 breaking changes
- Hop 2: v18 → v20 breaking changes
- Blocking dependency upgrades
- Manual audit patterns
- Infrastructure and tooling updates
- Security vulnerabilities to address

---

## Hop 1: v16 → v18 breaking changes

| Area                   | Change                                       | Action                                                                                       |
| ---------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| OpenSSL 3.x            | Legacy crypto algorithms removed or disabled | Test all crypto/TLS operations; add `--openssl-legacy-provider` as temporary workaround only |
| `Buffer()` constructor | Deprecated — throws in strict contexts       | Replace with `Buffer.alloc()` / `Buffer.from()`                                              |
| `fetch()`              | Now available globally (experimental)        | Remove `node-fetch` polyfill if only used for Node.js                                        |
| `AbortController`      | Stable, no longer needs import               | Remove any ponyfills                                                                         |
| npm                    | Ships with npm 9                             | Update lockfiles if needed                                                                   |

### Buffer constructor

```js
// Before
Buffer(size);
Buffer(string, encoding);

// After
Buffer.alloc(size);
Buffer.from(string, encoding);
```

### Grep for deprecated Buffer usage

```bash
grep -rn "new Buffer(" . --include="*.js" --include="*.ts"
grep -rn "Buffer(" . --include="*.js" --include="*.ts" | grep -v "Buffer\."
```

### OpenSSL temporary workaround (if needed)

```bash
export NODE_OPTIONS="--openssl-legacy-provider"
```

Remove this workaround once affected dependencies are upgraded.

## Hop 2: v18 → v20 breaking changes

| Area                        | Change                              | Action                                                     |
| --------------------------- | ----------------------------------- | ---------------------------------------------------------- |
| `fetch()`                   | Now stable (unflagged)              | Safe to use natively; remove any remaining polyfills       |
| ES modules                  | Stricter CommonJS/ESM interop       | Test mixed module usage; check `require()` of ESM packages |
| `--experimental-permission` | New permission model flag available | Opt-in only; no breaking change unless used                |
| V8 engine update            | Performance/security improvements   | Retest all crypto, regex, and numeric edge cases           |
| npm                         | Ships with npm 10                   | Run `npm install` to regenerate lockfile                   |

### Remove fetch polyfills

```bash
grep -rn "node-fetch\|cross-fetch\|isomorphic-fetch" . --include="*.js" --include="*.ts" --include="package.json"
```

If `node-fetch` is used only for Node.js compatibility (not for browser parity),
it can be removed:

```bash
npm uninstall node-fetch
```

## Blocking dependency upgrades

These packages are incompatible with Node.js 18+ and **must** be resolved before
switching versions.

### `node-sass` → `sass` (dart-sass)

`node-sass` uses native bindings that fail to compile on Node.js 18+ and ARM64.

```bash
npm uninstall node-sass
npm install sass --save-dev
```

Update build tool config (e.g. Gulp, webpack, vite) to use `sass` instead of
`node-sass`.

### `fs-promise` → native `fs.promises`

Package is abandoned and incompatible with modern Node.js.

```bash
npm uninstall fs-promise
```

```js
// Before
const fsp = require('fs-promise');
await fsp.readFile(path);
await fsp.writeFile(path, data);

// After
const fs = require('node:fs/promises');
await fs.readFile(path);
await fs.writeFile(path, data);
```

### `request` / `request-promise` → `undici` or native `fetch`

Both packages are deprecated and unmaintained.

```bash
npm uninstall request request-promise request-promise-native
npm install undici  # or use native fetch (Node 18+)
```

```js
// Before
const rp = require('request-promise');
const body = await rp('https://api.example.com/data');

// After (native fetch, Node 18+)
const res = await fetch('https://api.example.com/data');
const body = await res.json();
```

### `mongoose` v4/v5 → v8

Mongoose v4 is incompatible with Node.js 18+. This is a high-effort migration.

```bash
npm install mongoose@^8
```

Key breaking changes:

```js
// Before (v4 — callbacks)
mongoose.connect(uri, options, (err) => { ... });

// After (v8 — promises)
await mongoose.connect(uri, options);
```

- Callbacks removed — all operations return Promises
- `Model.remove()` → `Model.deleteOne()` / `Model.deleteMany()`
- `query.update()` → `query.updateOne()` / `query.updateMany()`
- See
  [Mongoose v8 migration guide](https://mongoosejs.com/docs/migrating_to_8.html)

## High-priority dependency upgrades

| Package         | Current | Target  | Reason                                          |
| --------------- | ------- | ------- | ----------------------------------------------- |
| `express`       | `^4.14` | `^4.21` | Security CVEs (see below)                       |
| `helmet`        | `^3.x`  | `^8.x`  | v3 incompatible with Node 20; major API changes |
| `connect-mongo` | `^2.x`  | `^5.x`  | Session store compatibility                     |
| `sequelize`     | `^5.x`  | `^6.x`  | Better Node.js 20 support                       |

### Helmet v3 → v8

```bash
npm install helmet@^8
```

```js
// Before (v3 — works with defaults)
app.use(helmet());

// After (v8 — review CSP directives explicitly)
app.use(
  helmet({
    contentSecurityPolicy: {
      directives: {
        defaultSrc: ["'self'"],
        styleSrc: ["'self'", "'unsafe-inline'"],
      },
    },
  }),
);
```

## Infrastructure and tooling updates

### `.nvmrc` / `.node-version`

```
20
```

### `package.json` engines — per hop

After hop 1:

```json
"engines": { "node": ">=18.0.0", "npm": ">=9.0.0" }
```

After hop 2 (final):

```json
"engines": { "node": ">=20.0.0", "npm": ">=10.0.0" }
```

### Dockerfile

```dockerfile
# Hop 1
FROM node:18-bookworm-slim

# Hop 2 (final)
FROM node:20-bookworm-slim
```

### TypeScript (`tsconfig.json`)

Node.js 20 fully supports ES2022:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022"]
  }
}
```

### CI/CD (GitHub Actions example)

```yaml
- uses: actions/setup-node@v4
  with:
    node-version: '20'
```

## Verification after each hop

```bash
npm install          # Rebuild native deps
npm audit            # Confirm no new critical CVEs
npm run test         # All test suites
npm run build        # Full build pipeline
```

Check for deprecation warnings in output — they signal the next things to fix.

---

## Notable v20 additions (no action required, but useful to adopt)

- `fetch()` stable — remove all HTTP polyfill packages used only for Node compat
- Built-in test runner (`node:test`) — consider replacing lightweight test
  setups
- `--experimental-permission` flag for sandboxing
- ~20% faster startup vs v16
